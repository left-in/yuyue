## 一、定下来的（2026-10-31）

1. **1.0 只做两样：气泡模式、有声书**（单独听 + 对齐）。先把现在就能做好的做出来。
2. **分角色朗读 1.0 之后做，分两种，同样重要**：
   - **传统**：每人一个声音，照原文念，不加语气、不加氛围；
   - **有语气、有氛围**：照原文写的“笑道”“冷笑道”演出来，有房间声和少量动静。
   两种是平级的两个选项，用户自己挑，不分谁是默认、谁是附加。
3. **两种都能自定义声音**：旁白和每个人物用什么声音、快慢高低，用户自己定；“我的声音”（自己录的）两种都能用。
4. 对齐换成**强制对齐**（第四节），先实测再动代码。
5. 不推销、不要账号、不收集数据；免费的本机就是完整的；只有一部手机也能用。

## 三、1.0 · 气泡模式

### 3.1 是什么
书切成聊天记录的样子看：旁白是段落，台词是气泡，气泡上有名字、首字头像、每人一种淡底色。是一种**看法**，排版里切换，不是默认；对话太少的书不显示这个选项。

听的时候（普通朗读、对齐好的有声书都行），正在读的那句亮起，页面跟着走；自己滑开后出现“回到朗读处”“从这里读”。点气泡从这句读；长按照常划线、写想法、问书伴。墨水屏只用细线框；读屏念成“黛玉说：……”。

### 3.2 谁说的：规则先定，决策模型做选择题，够把握才写名字
气泡只需要知道“这句是谁说的”，不需要声音。这一步做好了，以后两种分角色朗读直接用。

**查到的（2026-10-31）**：英文小说的标准测试集（PDNC，22 本、3.5 万句）上，现在最好的做法分三类台词：
| 台词 | 例子 | 最好的专门小模型 | 大模型（Llama-3 8B，看上下文） |
|---|---|---|---|
| 写明了名字 | “宝玉道” | 99.3% | 94.9% |
| 只写了代词 | “他说” | 95.5% | 93.1% |
| 什么都没写，靠上下文 | 一来一回的对话 | 89.3% | 81.8% |

中文：11 本小说的测试集上最好约 91%。
结论：**AI 看上下文确实能补上一大块，但“什么都没写”的那类，最好的也是十句错一句**；而且写明了名字的那类，规则比大模型还准。所以规则和 AI 各做各擅长的，再互相核对。

**三层**：
1. **规则**（核心里，三端一样，几秒做完整本）：
   - 写明了的：“宝玉道”“黛玉冷笑道”，取说话词前最近的人名。
   - 没名字但写了是谁：“外面人说”“一个丫头道”“众人笑道”，气泡上写“外面的人”“丫头”“众人”。
   - 第一人称：“我说”算主角“我”。
   - 代词：“他说”往前找最近的、还在这场戏里的男性人物；同场只有一个男的就定了。
   - 轮流说话：两个人一来一回，按“你一句我一句”推。
   - 别名：“宝玉”“宝二爷”“贾宝玉”合成一个人。
2. **决策模型做选择题**：规则定不了的台词，交给“决策模型”（2026-09 TypeSafe 的 Jev 带火的一类模型）。它不聊天、不写字，专门做有限的判断：给它整场戏的原文，问“这句是谁说的”，选项就是这场戏里在场的人（加上“众人”“不是台词”）。它**只能从选项里挑，不会编出一个不存在的名字**；每个选项给一个概率，号称“说 0.9 就是九成对”。
   - **整段对话一起定**：不是一句一句各判各的。决策模型给每句“像谁说的”打分，核心再把一整段对话连起来挑最说得通的一串（谁接谁的话、一来一回的顺序前后说得通）。查到的最准的做法就是“整段一起打分”，没写说话人的那类台词提升最多。
   - **过线才写名字**：最高的那个概率够高（比如 ≥ 0.9，第 0 步用答案章节定这条线），而且和规则的轮流推断不矛盾，才写名字；不够的画成灰色。原来想的“再问一遍核对”，由这个概率直接代替。
   - **在哪跑**（第 0 步实测后定）：
     - **本机，首选**：有开源、能商用的小决策模型，Strands Decider 2B（Apache-2.0）、Liquid d1-3B（年收入一千万美元以下能商用）。d1-3B 在 M5 Pro 上一次判断约 30 毫秒，一章几十句没把握的不到几秒。Mac 肯定跑得动；iPhone、Android 新机要测。免费、不用账号、书不出设备。
     - **云端**：Jev、pplx-decider 这类，每百万字约 0.04 美元，一整部《红楼梦》不到一毛钱人民币。给本机跑不动的设备，走用户自己在书伴里接的服务。
     - **都没有**：只有规则，剩下的灰着。
   - **要小心的**：这类模型才出来一个多月，几家排行榜结论不一样，TypeSafe 自己也说还没有一个能直接上生产；“0.9 就是九成对”在难题上被第三方测出不准；**中文行不行没人测过**。所以第 0 步要拿我们标好的章节实测，不信排行榜。
3. **以后更进一步：用我们自己的答案训练它**。决策模型的开源小模型能拿我们标好的中文章节再训练，变成“专门认说话人的中文小模型”。查到的最准的做法（英文 94.5%，比大模型还准、快上千倍）就是这种专门训练过的小模型。标得越多越准，1.0 之后做。

- 决策模型补的结果按书存下来、跟着同步：一台做过，别的设备直接用，不同设备之间不会一台写名字一台灰着。
- 同时记下（1.0 不用，留给分角色）：男女老少、心里话（“心想、暗道”）、语气（“笑道、冷笑道、哭道”）、停顿（“忙道”“半晌才道”、换场）。
- 一句里台词旁白混着的（“‘走吧，’他说，‘天要黑了。’”）按段记：台词进气泡，“他说”留在旁白。
- 英文同一套，换成 said / asked、he / she。

### 3.3 人物页（不剧透）
只列读到这里为止出场的人：名字、别名、台词多少；能定气泡在左还是在右。1.0 没有声音这一栏，分角色时再加。

## 四、1.0 · 有声书

### 4.1 单独听（三端）
- 导入 MP3、M4A、M4B，一个文件或一个文件夹（按文件名里的数字排，“第 2 集”在“第 10 集”前）；M4B 自带章节就用；封面、书名、作者读文件里的，能改。
- 倍速不变调、后退 15 秒 / 前进 30 秒、暂停后再播往回倒几秒、睡眠定时（含本章结束）、书签、锁屏和耳机按键。
- 进度按时间记，跟着同步；书架在读卡片照常显示、能“听”。
- 和朗读共用同一个播放器（锁屏、睡眠、统计都不另写）。
- **同步默认只传进度、书签和对齐结果**，录音每台设备自己导入，靠文件指纹认出同一本；设置里留“连录音一起同步”。

### 4.2 对齐：换成强制对齐
**现在的做法**的问题：只有 iOS 26 / macOS 26 能用，Android 不能；转写要猜“说了什么”，猜错的字、人名会让比对出岔子；句子边界靠转写的词时间，不够准。

**强制对齐**：书里的字是已知的，不用猜。声学模型把录音变成“每一小段时间像哪个音”，再把书里的字（中文转成拼音）沿着录音排进去，直接得出每句话的起止。开源的有声书同步工具 Storyteller 就从“先转写再比对”换成了这种做法（用 Meta 的多语言模型 MMS）。

**拼起来**：
1. **先粗**：用现在 align.rs 的“找锚点”比对，定出每一大块录音对应书里哪一段（片头片尾、主播漏读多读的地方在这一步剥掉）。
2. **再细**：每块里做强制对齐，得出每句的起止；分块也防长录音越对越偏。
3. **对不上的**照旧：录音里没有的句子用朗读补，对得不准的列进检查窗口。

**实测（2026-10-31，M2，实验在 T2214/yuyue-lab/align）**：Meta 的 MMS 对齐模型，中文先转拼音；和“Whisper 听写 + 现在的 align.rs 比对”并排比。检验方法：按对齐结果把每句剪出来再听写一遍，和原文比。

| | 现在的做法 | 强制对齐 |
|---|---|---|
| 《孔乙己》11 分钟：句子切得准 / 头尾都对 | 87.1% / 73.0% | 87.7% / 74.3% |
| 《傲慢与偏见》1–4 章 27 分钟：句子切得准 / 头尾都对 | 93.9% / 89.6% | 90.3% / 87.5% |
| 要多久（中文 / 英文） | 123 秒 / 202 秒 | 23 秒 / 57 秒 |

- **准度差不多，快 4～5 倍，三端都能做**。英文差的那点主要是书里的插图说明录音里没念，现在的做法会跳过，强制对齐还没做“中间跳过”；检验用的也是 Whisper，偏向对照组。
- 实测里补上的三件事，正式做要带上：录音里多出来的话（片头、“本录音由某某提供”）用“垃圾符号”跳过，每帧扣 0.2 分最合适；不强求对到书的最后一个字（书末的注释没念）；两句之间的停顿从中间劈开分给前后两句。
- 还要做：**中间跳过**（插图说明、注释、主播漏读的段落）；**手机上的速度**。模型瘦身已做（2026-11-01）：8 位约 300 MB，两本书检验准度和原模型一样（孔乙己 88.3% / 75.7%，傲慢与偏见 91.0% / 88.2%）。
- **许可**：MMS 的权重是 CC-BY-NC 4.0，只许非商用。语阅不收钱（打赏已删，2026-11-01），开源许可里署名。
- 顺带发现：Gutenberg 那种每行硬换行的 TXT，导入后句子在行尾被切断、目录也认不出来（《呐喊》），要另修。

**拼音从哪来**：核心里新做一份读音（多音字词表 + 规则、数字单位、人名全书一种读法）。这一份以后分角色朗读纠正读音也用得上。

### 4.3 配上电子书
- 单独听的有声书，书架上正好有这本电子书时提示“可以合成听读书”；对齐好以后进度从“按时间”换成“按句子”，接得上。
- 对齐好的书在气泡模式里也能亮。

## 五、1.0 之后 · 分角色朗读（两种，同样重要）

先把共用的打好，再分别做两种的声音。

| | 传统 | 有语气、有氛围 |
|---|---|---|
| 认人、别名、心里话、停顿 | 用 1.0 的剧本 | 同左 |
| 没把握的台词 | 旁白的声音念 | 同左 |
| 声音 | 系统、高级、云端、本机模型、我的声音，都能选 | 同左；按语气演，需要能演语气的声音（本机模型、云端） |
| 语气 | 不加 | 照剧本里的“笑道、冷笑道……”演 |
| 氛围 | 不加，句间正常停顿 | 极轻的房间声、少量动静（门、脚步、雨）；音乐默认关 |
| 读音 | 1.0 的读音 | 同左 |

### 5.1 声音自己定（两种共用）
- **App 先配一遍**：旁白用“我的 · 朗读”里挑的那个；人物按男女老少挑，台词多的先挑，**同一场戏里一起出现的人给最不像的声音**（每个声音两两像不像，我们事先量好打进 App）。
- **用户改**：人物页里每个人物一行，点开选声音（边选边试听这个人的一句台词），两个滑条调快慢、高低；旁白在最上面也能换。改了从下一段起生效，App 不会再改回去。
- **我的声音**：录 30 秒（或导入一段），检查够不够干净，马上试听；能配给旁白或任何人物。只在自己设备上，不能导出；导入的要勾“这是我的声音，或者我得到了本人同意”。
- 配好的按书存、跟着同步；另一台设备上没有这个声音时用 App 配的那个，不报错。同一系列的下一本沿用。

### 5.2 先后
1. 共用的：播放器从“一句一个声音”改成“一段一个声音”、App 先配、人物页声音栏和快慢高低、停顿。
2. 传统：用系统、高级、云端声音就能做，最先能交。
3. 有语气、有氛围：要本机模型演语气（每个声音事先录好几种语气的样音，小模型照着念）、氛围声道；按设备挑，跑不动的设备只显示传统。
4. 我的声音：和本机模型一起做（同一个克隆模型），两种都能用。
5. 云端（用户自己选、自己付）、背景音乐：再往后。

| 风险 | 什么时候知道 | 退路 |
|---|---|---|
| 强制对齐在中文上不准，或模型太大太慢 | 第 0 步 | Apple 保留“转写再比对”，强制对齐只补它对不上的块；Android 先用 Mac / iPhone 对好的结果 |
| 网文上没把握的台词太多，气泡一片灰 | 第 0 步 | 提示“接上书伴的 AI 能认出更多”；灰的超过一半的书不显示气泡选项 |
| 决策模型中文不行，或者概率不准（说 0.9 实际只有七成） | 第 0 步 | 线抬高；还不行换普通大模型做选择题；再不行只用规则 |
| 中文有声书文件少（国内平台都加密） | — | 介绍里写清能导哪些：网盘里的 MP3 / M4B、公版录音、无 DRM 的有声书、自己录的 |

## 九、不做（以后想做再提）
- 改说话人、整本先录好、夜里录音、Windows 录音助手、人物小传和导演本。
- 语阅卖云端额度、服务器上的公版剧本。
- EPUB3 媒体覆盖层（以后；强制对齐的结果正好能导出成它）。

## 十、要你定的

1. **认说话人用决策模型补**：规则定不了的，交给决策模型从在场的人里挑，概率过线才写名字，剩下的画成灰气泡；优先在本机跑开源的小决策模型，跑不动的设备用云端。
   **建议**：照这个。第 0 步拿答案章节实测，中文不行就退回普通大模型（用户书伴里接的、苹果本机模型）。
