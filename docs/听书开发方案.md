## 一、定下来的（2026-10-31，11-03 改）

1. **1.0 做四样：气泡模式、分角色朗读、克隆声音、有声书**（单独听 + 对齐）。
2. **1.0 的分角色朗读：能分，默认不分**（2026-11-03 定；11-07 定做法，见 5.1）：
   - **默认全书一个声音**（“我的 · 朗读”里挑的那个），用户不设置，听起来和现在的朗读一样；
   - 人物页里旁白、对话、每个人物都能单独设声音和快慢高低；只给“对话”换个声音，就是旁白一个声音、台词一个声音，不用认人；
   - 认错了说话人能当场改；
   - 不加语气、不加氛围，照原文念。
3. **1.0 能克隆声音**：录一段或导入一段，克隆出一个声音，能配给旁白、对话或任何人物（第五节）。
4. **1.0 之后（更难）**：照原文的“笑道”“冷笑道”带语气演，加房间声和少量动静；App 默认就给每个角色配各自的声音。
5. 对齐换成**强制对齐**（第四节），先实测再动代码。
6. 不推销、不要账号、不收集数据；免费的本机就是完整的；只有一部手机也能用。

## 三、1.0 · 气泡模式

### 3.1 是什么
书切成聊天记录的样子看：旁白是段落，台词是气泡，气泡上有名字、首字头像、每人一种淡底色。是一种**看法**，排版里切换，不是默认；对话太少、或分不出台词（没有引号）的书不显示这个选项。

听的时候（普通朗读、对齐好的有声书都行），正在读的那句亮起，页面跟着走；自己滑开后出现“回到朗读处”“从这里读”。点气泡从这句读；长按照常划线、写想法、问书伴，台词上多一项“谁说的”（5.1.4）。墨水屏只用细线框；读屏念成“黛玉说：……”。

### 3.2 谁说的
气泡和分角色朗读用同一份剧本（5.1.2）。认出来的台词，气泡上写名字、首字头像、这人的颜色；“众人”这类一群人的写“众人”，不放头像；没认出来的是灰气泡，不写名字。长按台词能改是谁说的（5.1.4）。

### 3.3 人物页
和分角色朗读同一页（5.1.3），气泡在左还是在右也在这里定。

## 四、1.0 · 有声书

### 4.1 单独听（三端）
- 导入 MP3、M4A、M4B，一个文件或一个文件夹（按文件名里的数字排，“第 2 集”在“第 10 集”前）；M4B 自带章节就用；封面、书名、作者读文件里的，能改。
- 倍速不变调、后退 15 秒 / 前进 30 秒、暂停后再播往回倒几秒、睡眠定时（含本章结束）、书签、锁屏和耳机按键。
- 进度按时间记，跟着同步；书架在读卡片照常显示、能“听”。
- 和朗读共用同一个播放器（锁屏、睡眠、统计都不另写）。
- **同步默认只传进度、书签和对齐结果**，录音每台设备自己导入，靠文件指纹认出同一本；设置里留“连录音一起同步”。

### 4.2 对齐：换成强制对齐
**现在的做法**的问题：只有 iOS 26 / macOS 26 能用，Android 不能；转写要猜“说了什么”，猜错的字、人名会让比对出岔子；句子边界靠转写的词时间，不够准。

**强制对齐**：书里的字是已知的，不用猜。声学模型把录音变成“每一小段时间像哪个音”，再把书里的字（中文转成拼音）沿着录音排进去，直接得出每句话的起止。开源的有声书同步工具 Storyteller 就从“先转写再比对”换成了这种做法（用 Meta 的多语言模型 MMS）。

**拼起来**：
1. **先粗**：用现在 align.rs 的“找锚点”比对，定出每一大块录音对应书里哪一段（片头片尾、主播漏读多读的地方在这一步剥掉）。
2. **再细**：每块里做强制对齐，得出每句的起止；分块也防长录音越对越偏。
3. **对不上的**照旧：录音里没有的句子用朗读补，对得不准的列进检查窗口。

**实测（2026-10-31，M2，实验在 T2214/yuyue-lab/align）**：Meta 的 MMS 对齐模型，中文先转拼音；和“Whisper 听写 + 现在的 align.rs 比对”并排比。检验方法：按对齐结果把每句剪出来再听写一遍，和原文比。

| | 现在的做法 | 强制对齐 |
|---|---|---|
| 《孔乙己》11 分钟：句子切得准 / 头尾都对 | 87.1% / 73.0% | 87.7% / 74.3% |
| 《傲慢与偏见》1–4 章 27 分钟：句子切得准 / 头尾都对 | 93.9% / 89.6% | 90.3% / 87.5% |
| 要多久（中文 / 英文） | 123 秒 / 202 秒 | 23 秒 / 57 秒 |

- **准度差不多，快 4～5 倍，三端都能做**。英文差的那点主要是书里的插图说明录音里没念，现在的做法会跳过，强制对齐还没做“中间跳过”；检验用的也是 Whisper，偏向对照组。
- 实测里补上的三件事，正式做要带上：录音里多出来的话（片头、“本录音由某某提供”）用“垃圾符号”跳过，每帧扣 0.2 分最合适；不强求对到书的最后一个字（书末的注释没念）；两句之间的停顿从中间劈开分给前后两句。
- 还要做：**中间跳过**（插图说明、注释、主播漏读的段落）；**手机上的速度**。模型瘦身已做（2026-11-01）：8 位约 300 MB，两本书检验准度和原模型一样（孔乙己 88.3% / 75.7%，傲慢与偏见 91.0% / 88.2%）。
- **中间跳过先做，比换模型更要紧**（2026-11-02）：现在多出来的话只在章头章尾能跳，真的有声书里主播漏读、注释、插图说明在章中间，一处对不上后面就跟着偏。做法和跳片头同一类：对齐时允许跳过一句或几句，每跳一次扣一点分。
  - **已做（2026-11-04，forced.rs）**：一句念完可以直接跳到后面第 2～13 句的开头，每跳一次扣 12 分、每跳过一句再扣 2 分；跳过的句子算“录音里没有”，用朗读补。真录音上测过（T2214/yuyue-lab 里存的模型输出）：往书里插两句没念的“插图说明”，《孔乙己》旧做法后面 85 句错位 84 句，新做法 0 句；《傲慢与偏见》1–4 章 113 句 0 句错位。原样不插时，新做法把旧做法硬塞进去、听清只有 0～0.26 的 21 句跳过了（Gutenberg 本里的插图说明，录音没念），后一句的听清度跟着上升，其余句子不变。第一版有个毛病：跳到前面的状态一时分数最高，搜索窗口跟着往前挪，真正念到的地方掉出窗口，《傲慢与偏见》末尾 3 句念了的被跳掉；改成窗口往回多留、一次最多跳约 400 个字母后，这 3 句回到原位。还没用人工标的答案量。录音里**多出来**的话：
  - **已做（2026-11-04 下午）**：两句之间的停顿也能装下书里没有的话（广告、“本节目由……”、主播插的一句），每听到一个字母扣 2 分。装下的那段不算进前后两句，按句播放时直接跳过。原来的做法遇到这种话，后面并不会全偏，但挨着的那一两句会把它吞进去（例：一句从 5.7 秒拉长到 13 秒，有时还丢掉一句短句），听的时候那句里夹着广告、高亮停 15 秒。
  - 测法：在《孔乙己》《傲慢与偏见》存好的模型输出中间，按句子边界塞进 15 秒别的话（同一个人念的别处、另一种语言），两个位置、六种组合共 12 次。旧做法每次那 15 秒都还在句子里播；新做法 9 次整段跳过，后面的句子 12 次里只有 2 句错位。剩下没跳干净的是《孔乙己》结尾一串很短的对话句。原样不插时只多出两处空洞，一处是主播把第 197 句念走了样（少念半句）——旧做法把它塞进第 196 句、再用朗读补一遍 197，等于念了两遍；新做法只朗读补一遍。
  - 扣分试过 1.0 / 1.5 / 2.0 / 2.5 / 3.0，2.0 最稳。
- **这些数字还不能说明行不行**（2026-11-02）：检验是把剪出来的句子再让 Whisper 听写，Whisper 自己的错也算进去了。改成人工标：中英文各 5 分钟，标出每句的起止，量对齐结果差多少毫秒；高亮差 0.3 秒以内看不出来，所以看“差超过 0.3 秒的句子占多少”。
- **许可**：MMS 的权重是 CC-BY-NC 4.0，只许非商用。语阅不收钱（打赏已删，2026-11-01），开源许可里署名；从 GitHub 发的模型包里也带上许可和署名。以后只要沾一点收费就得换，所以第 0 步顺带测一个能商用的：中文 WeNet / sherpa-onnx 的 CTC 模型、英文 wav2vec2 系列（许可要再核实）。上面实测两种做法准度差不多，说明准不准主要看对齐的算法；能商用的模型准度相当就换，最好还更小。
- 顺带发现：Gutenberg 那种每行硬换行的 TXT，导入后句子在行尾被切断、目录也认不出来（《呐喊》），要另修。

**拼音从哪来**：核心里新做一份读音（多音字词表 + 规则、数字单位、人名全书一种读法）。这一份分角色朗读纠正读音也用得上。

### 4.3 对齐结果：一台对好，别的直接用（2026-11-02）
- 对齐结果（每句起止，几百 KB）跟着同步。哪台设备先对好，别的设备直接用，不用下模型、不用再跑。
- 谁来对：有 Mac 的默认在 Mac 上对；只有手机的在手机上对（第一次用时下模型）。手机跑不动的，提示“在另一台设备上合成后会自动同步过来”。
- 手动改过的句子跟着同步，重新对齐也不覆盖。
- 配对关系（哪本有声书配哪本电子书）也跟着同步。
- **已做（2026-11-04）**：核心 listening.rs，同步日志里一本录音一条 `listen/<有声书 id>`：配哪本电子书、片头、做完没有，每章一格存每句起止（毫秒）、听清多少、是不是手动改过。只写变了的那几章，重新对齐一遍不会把日志撑大；归在“进度和书签”里同步。Mac / iPhone、Android 存对齐结果时都写进去；同步回来后，书架上有同一本有声书（自己导入的、id 一样）就直接用，Mac / iPhone 还会自动配上电子书。以前在本机合成好的，下次打开时补写进日志。没在两台真设备之间试过。
  - **改（2026-11-04 下午）**：在一台设备上“删掉这本有声书”只删这台的，同步日志里的对齐结果留着（别的设备还有自己的录音），这台也不会再被同步自动配回来，除非再手动合成。原来删的时候会把日志里那条一起清掉，可别的设备随后又把自己的补写回去，等于没删，还会在这台自动配回。
  - **录音同步拆开（2026-11-04 下午，照 4.1 节）**：同步设置里“书文件和有声书”拆成“书文件”（默认开）和“有声书录音”（默认关，几百 MB）。关着时只同步对齐结果，另一台设备导入同一份录音就能直接听。手机上两项都只在 Wi-Fi 下传。

### 4.4 配上电子书
- 单独听的有声书，书架上正好有这本电子书时提示“可以合成听读书”；对齐好以后进度从“按时间”换成“按句子”，接得上。
- 对齐好的书在气泡模式里也能亮。

## 五、1.0 · 分角色朗读和克隆声音

### 5.1 分角色：能分，默认不分（2026-11-03 定，11-07 定做法）
听起来是这样：
- **什么都不设**：全书一个声音，和现在的朗读一模一样。
- **人物页上三层**：最上面“旁白”“对话”两行，下面是一个个人物。旁白默认是“我的 · 朗读”里挑的那个；对话默认跟旁白；每个人物默认跟对话。
- **只换“对话”**：引号外旁白一个声音，引号里另一个声音。只看引号、不用认是谁说的，不会认错，最省事。
- **再给人物设**：宝玉、黛玉各设一个，认出是他们说的台词用他们的声音；没认出来的、“众人”说的用对话那行的声音。给对话也换一个，台词就不会突然变回旁白念。
- **一句里按段换**：“宝玉笑道：‘你来了。’”里，“宝玉笑道”旁白念，引号里宝玉念。
- 每行都能调快慢、高低；能选系统、高级、云端、克隆的声音。
- 第一人称的书（“我说”），人物页最上面多一行“我”，默认跟旁白：讲故事的人就是“我”。
- 不加语气、不加氛围，照原文念；“笑道”这些说话词照念。

#### 5.1.1 原则
- **宁可认不出，不要认错**：认不出只是“不是他的声音”，认错了是“这句话成了别人的”。规则只认书上写明的（包括省了主语、看前一句就知道的），要推断的交给 AI 和你。
- **谁说了算**：你改的 > 规则（书上写明的）> AI 补的 > 认不出（灰气泡、对话的声音）。规则和 AI 都不覆盖你改的。
- 没写说话人的台词，最好的自动做法也十句会错一句左右，所以 1.0 就要能当场改（5.1.4）。

#### 5.1.2 剧本（核心里做，三端一样）
- **每句拆成段**：旁白段、台词段（引号里的）。心里话（“心想：‘……’”）1.0 算这人的台词，以后单独成一种段。一句台词跨几句时，是同一句台词、同一个人。
- **台词段记**：谁说的（一个人物 / 众人 / 认不出）、怎么定的（你改的 / 写明 / 承前 / AI）。
- **找台词**：成对的“”「」『』和英文 “” ‘’；直引号 " 按开合配对，英文的撇号（don't）不算。一段结尾不收引号、下一段又开引号的，算同一句台词接着说；台词里套的引号（“他说‘你来’”）还是外面那人的台词。书名号里的、“写着”“题着”后面的、句子中间两三个字的（强调、引用的词），算旁白。
- **规则认人**（书上写明的，和省了主语、照前面一看就知道的）：
  1. 说话词在前、在后、在中间：宝玉道：“……” /“……”宝玉道。/“……”宝玉道，“……”；英文 said Mr. Darcy / Darcy said。
  2. 一群人：众人、丫头们、外面的人，记“众人”。
  3. 承前：说话词前没写是谁，这句或上一句里只有一个人在做事，就是他；“说着又道”接上一句的同一个人。
  4. 第一人称：“我说”“我道”“I said”记“我”。
  5. 一来一回、代词（“她说”“he said”）这类要推断的，先不进规则；考卷上（5.1.7）量过、几乎不错再加。
- **人物表**：从说话词前后的名字里收，中文、英文都收。每人：名字、别名、男 / 女 / 不知道、台词多少、第一次说话在第几章。
  - **只合确凿的**：全名带短名、书里没有别人也这样叫（贾宝玉 = 宝玉，书里有甄宝玉就不合）；只差个“儿”（凤姐儿 = 凤姐）。称呼、外号、换了叫法的（凤姐 = 王熙凤）不合，AI 提示、你来合。宁可一个人分两行，也不把两个人并成一个。
  - 男女：称呼（太太、姑娘 / 老爷、公子）、现代文的“她”、英文 Mr. / Mrs. / Miss；定不了写“不知道”。只用来排序挑声音，不替你配。
  - **一个人认一组名字**：声音、你改的都跟着这一组；规则升级、合并拆开之后，只要还有一个名字对得上就接得上。App 只拿核心给的人物编号，不自己比名字。
- **什么时候做**：第一次开气泡、打开人物页或设了声音时，后台把整本做一遍，正在读的这章先做；导入时不做。要做到整本几秒。
- **存**：按书存本机，带版本（规则、书的文字、替换规则变了就重做）。规则算出来的每台设备一样，不同步；同步的只有你改的、AI 补的和声音设置。播放器、气泡、人物页都只读剧本。
- 替换规则照常改念出来的字：先拆段，再在段里替换，段的边界不跟着挪。
- **分不出台词的书**（破折号对话、“张三：……”聊天体、没有引号的 TXT）：1.0 不分，人物页写“这本书分不出台词”，全书一个声音。

#### 5.1.3 人物页
- 从听的面板“分角色”和气泡模式进来。最上面旁白、对话两行（第一人称的书多一行“我”），下面是读到这里为止说过话的人，不剧透，台词多的在前；一行：首字头像、名字（别名小字）、台词多少、用的声音。
- 点一行：换声音（边选边试听这个人的一句台词，按男女把合适的排前面）、快慢、高低、气泡在左还是在右；改名字、改男女、合并、拆开。
- 给人物设了声音、对话还跟着旁白时，对话那行提一句“没认出的台词用这个声音”。
- 整本还没做完时，顶上写“正在认人物 · 第 40 / 120 回”。
- 设的按书存、跟着同步；同一系列的下一本按名字沿用。另一台设备上没有这个声音，或这个声音不会念这种语言：按人物 → 对话 → 旁白往上找一个能用的，人物页上写明，不报错。
- 先改原型（docs/design/听书-分角色与克隆声音.html：加对话那行、“谁说的”、合并拆开），你确认再写。

#### 5.1.4 认错了：当场改
- **长按台词 →“谁说的”**：列这章说过话的人（最近说过的在前）、“众人”“不是台词”“新的人物…”；选了马上生效，这章剩下的跟着重算。
- **听的时候**：分了角色的书，听的面板上写正在说话的人，点名字是同一张名单。
- **人物页**：改名字、改男女、合并（凤姐 + 王熙凤）、拆开（把并错的名字分出去）。
- 改的按书存、跟着同步；规则升级、AI 重认都不覆盖。按“第几章第几句 + 台词开头几个字”记，和划线一样；书换了版本对不上的不硬套，人物页底下写“有 3 处改过的对不上了”。

#### 5.1.5 AI 补认不出的（接了 AI 才有）
- 书伴里接了 AI 服务才出现，默认关。人物页上按书打开，打开前写清：这本书的字会发给你接的哪个服务。
- **按章问**：这章原文，台词编好号；规则定了的作为已知给它，只问认不出的。选项是这章和前几章说过话的人，加“众人”“不是台词”“别人（写名字）”。要它回一张表，每句一个选项。
- **核对**：不在选项里、原文里找不到的名字、和规则定的矛盾的，不收，仍是认不出。
- 顺带问“这几个名字是不是同一个人”“是男是女”：只在人物页提示“可能是同一个人：凤姐、王熙凤”，你点了才合。
- 读到哪章补到哪章，人物页上能“整本都补上”；补的按书同步，一台补过，别的不再花钱。
- 先接书伴里的大模型；以后有本机跑得动的模型，接同一个口子换掉，界面不变。
- 时间紧时这块放到 1.0 之后，不影响上面几节。

#### 5.1.6 播放：按段念
- 进度、高亮、跳转、本句读完、睡眠定时、锁屏还是按句。
- 一句里相邻、同一个声音的段先合起来；整句一个声音就和现在一样整句合一次。不设分角色时什么都不变。
- 一句里有几个声音：每段各自合成，切掉头尾的静音，拼成一句播；换声音处留约 0.2 秒，同一个声音的段之间不留（数照听感调）。
- **音量**：每个声音第一次用时量一次响度，往旁白靠，存下来。语速不自动对，靠人物页的快慢；整本的倍速照常对整句。
- **快慢、高低**：对所有声音都有效，三端一样（系统声音用它自己的，云端、克隆的合成后再变）。Android 拼之前先统一采样率。
- **云端**：按“声音 + 快慢高低 + 这段的字”缓存；提前合成只合这个声音自己要念的段。
- 改了人物页，从下一句起生效。
- 有声书：原声的句子照原声，用朗读补的句子照分角色念。播客照旧用主持人的声音，不走分角色。

#### 5.1.7 怎么考（和界面一起做，不挡界面）
- **调规则用的**：《红楼梦》第八回（已有答案）。
- **只打分、不许拿来调规则的**：《红楼梦》另一回、鲁迅一篇对话多的小说、一章网文写法、一章翻译小说、一章英文小说。用公版书或自己写的同类文字，答案能放进仓库。
- **量什么**：写明 / 承前 / 没写三类台词各认对、认错、认不出多少；人物并错几对；不是台词被当成台词几处；整本《红楼梦》、两千章网文要多久。
- **线**：只用规则时认错 ≤ 1%（写明名字的 0 句）、主要人物并错 0 对；接了 AI 认错 ≤ 5%、认不出 ≤ 一成；整本《红楼梦》几秒、两千章网文一分钟内。
- 进 `cargo test`：比上次差就不过。
- **听着考**：给对话和两个主要人物各设一个声音听一章：“宝玉笑道”是旁白的声音；换声音处不顿、不忽大忽小；念错人的地方当场改得了。

### 5.2 克隆声音（1.0）
- 录 30 秒，或导入一段干净的录音；检查够不够干净（噪声、混响、有没有别人说话），马上试听。
- 克隆出的声音进声音列表，能配给旁白、对话或任何人物，普通朗读也能用。
- 只在自己设备上，不上传、不能导出；导入别人的录音要勾“这是我的声音，或者我得到了本人同意”。
- **在哪跑**（第 0 步实测后定）：本机克隆模型优先（中英文都要像、能商用、Mac 和手机的速度）；本机跑不动的设备，用户自己在设置里接的云端克隆（ElevenLabs 已接好）。候选的开源模型和许可第 0 步核实。
- 这是 1.0 里最没把握的一块。

**实测（2026-11-03，M2 16 GB，MLX 8 位，实验在 T2214/yuyue-lab/clone，试听页 clone/out/试听.html）**：LibriVox 的中文（《孔乙己》）、英文（《傲慢与偏见》）朗读者各一段做参考，克隆后念《红楼梦》第八回一段、《傲慢与偏见》一段。像不像用 CAM++ 声纹相似度（两个不同的人之间是 0.13），清不清楚用 Whisper 转写回来的错字率（真人原声本身：中文 9.4%、英文 2.8%，中文错的多是同音字）。

| 模型（都是 Apache-2.0） | 磁盘 | 速度（生成用时 ÷ 音频长，<1 才跟得上播放） | 像不像：同语言 / 跨语言 | 错字率：中 / 英 |
|---|---|---|---|---|
| Qwen3-TTS 0.6B，8 秒参考 | 1.9 GB | 0.96～1.07 | 0.85～0.88 / 0.56～0.76 | 13～14% / 2% |
| Qwen3-TTS 1.7B，8 秒参考 | 2.9 GB | 1.2～1.45 | 0.89～0.92 / 0.55～0.81 | 10～11% / 0% |
| Qwen3-TTS 0.6B / 1.7B，25 秒参考 | 同上 | 1.0～1.3 / 1.3～1.5 | 和 8 秒差不多 | 差不多 |
| VoxCPM2 2B，25 秒参考 | 3.0 GB | 3.1～4.6 | 0.84 / 0.52～0.84 | 10～11% / 0% |

- **像、也清楚**：同语言都明显是同一个人，中文错字率和真人原声差不多。英文参考念中文时最不像（0.43～0.56，声纹模型是中文的，也可能偏低），中文参考念英文还行（0.76～0.83）。
- **慢**：在 M2 上没有一个比念得快，最快的 0.6B 也只是刚好跟上；VoxCPM2 慢 3～4 倍，不考虑。参考录音 8 秒就够，长了反而慢。
- **大**：0.6B 磁盘 1.9 GB、跑起来内存 6 GB 以上，手机上照这样跑不动。
- **结论（等你听过再定）**：Mac 上能用 Qwen3-TTS 0.6B 克隆，但要像云端声音那样**提前合成这一章**，不能边念边生成；手机先走自己接的云端克隆，或者用 Mac 合成好的音频（要另想怎么同步过去）。接下来要试：把 0.6B 转成 Core ML / 4 位看手机上能不能跑、内存能不能压到 2 GB 以下。

## 八、风险和退路

| 风险 | 什么时候知道 | 退路 |
|---|---|---|
| 强制对齐在中文上不准 | 第 0 步 | 先补中间跳过、换模型再测；还不行，1.0 只上单独听，合成标“试用”（“转写再比对”已在 2026-11-01 删掉，不再是退路） |
| 模型在手机上太大太慢 | 第 0 步 | 用别的设备对好同步过来的结果（4.3 节）；只有一部手机又跑不动的，说明要较新的手机 |
| MMS 只许非商用，以后想收费就不能用 | 第 0 步 | 换能商用的 CTC 模型（第 0 步一起测） |
| 网文里没写说话人的台词多，认不出的多 | 第 3 步考卷 | 认不出的用对话的声音念，听着不乱；人物页提示“接上书伴的 AI 能认出更多”；灰的超过一半的书，气泡选项收起来 |
| AI 补认中文不准 | 第 6c 步考卷 | 先只收和规则、前后不矛盾的；还不行，打乱选项再问一遍、两遍一样才收；再不行这块不上，只用规则和你改的 |
| 按段念一句里顿好几下、听着碎 | 第 6 步 | 切掉每段头尾的静音、同一个声音的段不停；还不行，短的说话词（“他道”）并进台词那段 |
| 你改过的说话人在书换了版本后对不上 | 第 6b 步 | 按“第几章第几句 + 台词开头几个字”找回；找不回的列出来“有 3 处改过的对不上了”，不硬套 |
| 剧本、按段念、当场改加起来，1.0 的活多了一块 | 现在 | 时间紧先挪走 AI 补认（6c）；剧本、按段念、当场改不挪：少了它们，一设声音就会念错 |
| 本机克隆在手机上太慢，或中文不像 | 第 0 步 | 手机用自己接的云端克隆；Mac 照常本机；都不行，1.0 的克隆只在 Mac 上 |
| 用户给人物设了不同声音，认错人就念错声音 | 第 3、6 步 | 规则只认写明的；认不出的用对话的声音；默认一个声音时听不出来；听出来了当场改（5.1.4） |
| 设备上的系统声音少，几个人物分不开 | 第 6 步 | 同一个声音调快慢高低也能分开；云端、克隆的声音都能配 |
| 中文有声书文件少（国内平台都加密） | — | 介绍里写清能导哪些：网盘里的 MP3 / M4B、公版录音、无 DRM 的有声书、自己录的 |

## 准度实测（2026-11-04）

不靠人标：`scripts/align-bench/build.py` 拿每句单独录好的语音按顺序拼成一本“有声书”，每句从哪儿开口、到哪儿说完是精确知道的；`run.py` 跑核心的对齐，自动打分。数据在实验盘 bench/，换算法后重跑一遍几分钟（模型输出存着）。

- 考卷：LibriSpeech test-clean 三章（英文，一个人读一章）；FLEURS 普通话 150 句（中文真人，一句换一个人，录音噪声大）；《孔乙己》172 句用系统中文声音念（书的原文：繁体、引号、注释）。每本四种：照读、约 6% 的句子没念、开头和中间插 50 秒左右不在书里的话、两样都有。共 2120 句、约 4 小时。
- 怎么算错：起点没落在“上一段话说完 → 这句开口”的停顿里，差超过 0.3 秒；念了却说没有；没念却给了时间。另外量“不在书里的话被放出来几秒”。
- 结果（这一版）：
  - 英文：0–5.5%，平均约 2%，基本达标。
  - 中文《孔乙己》：照读 4.1%，有插话的 6–9%；有一份插话的 61 秒里放出 43 秒。没达标。
  - 中文 FLEURS：9–23%。其中一部分是考卷本身的问题（噪声被当成开口，Whisper 核对过），但也有真错：一句整句念了，算法判成没念，下一句的起点落到它头上。
  - 插话：总共 671 秒，放出 56 秒（中间跳过加插话这一版之前是放出约四分之三）。
- 这次修的：年份按位读（“1978 年”读一九七八，原来按数目读成一千九百七十八，整句对不上被跳过），总错率 7.4% → 6.8%。
- 试过没留：把句间停顿拆成“安静—可以有话—安静”，不让“跳过一句 + 把它的声音当插话”同时发生。有的好了有的坏了（一份漏了 39 句），总的更差，撤了。
- 还要做：中文的“整句判成没念、下一句顶上”；起点普遍早 0.4–0.7 秒的那一类；找一份干净的中文真人连续朗读当考卷（FLEURS 太吵，答案不够准）。
