# 语阅 · 多角色听书 规划（第二版）

> 日期：2026-10-19 ｜ 状态：方向已定，等实测 ｜ 关联：FEATURES.md 3.3 听书、3.4 听读对齐、3.8 AI 书伴；TECH.md 五、六、八

## 改了什么（相对第一版）

- 你定了：功能捡回来；**目标是有感情、有语气，必须做到**；没有模型的设备不能将就；气泡左右由用户定；人物表不剧透；接下来主做这个功能，先画原型。
- 第一版是照着别家的做法拼的（规则 + 系统语音分角色，语气靠云端）。这一版从头想：**多角色听书本质上是把一本书做成广播剧**，按做广播剧的流程来设计，而不是在"朗读"上加功能。

---

## 一、一句话

把任何一本小说，在你自己的设备上，做成一部有演员、有导演、有感情的广播剧；听的时候可以切到气泡排法，谁在说话，谁的气泡亮。

**目标（2026-10-19 你定的）：把书里的人还原成真人。** 不是给台词贴一个"高兴""生气"，而是想清楚：这个人要是真活着，以他的年纪、出身、脾气、和对面这个人的关系、此刻心里的事，这句话会怎么说出口。下面每一步都为这个目标服务。

---

## 二、核心想法：先"录制"，再"播放"

现在的朗读是**边念边播**：每句话在播放前一刻才合成，所以只能用很快、很小的声音，没法讲究语气。

多角色听书换个做法，像真的录有声书一样分两步：

```
  制作（慢、一次性、在后台）                            播放（和现在一样）
┌─────────────────────────────────────────────┐
│ ① 写剧本   ② 选演员   ③ 录音   ④ 对时间      │  ─►  逐句高亮、气泡、倍速、
│ 谁在说话   每人造一个  一段一段  切回每一句  │       睡眠定时、锁屏……全都照旧
│ 怎么说     专属声音    带感情地录           │
└─────────────────────────────────────────────┘
```

**为什么这样更好：**

1. **不赶时间，就能用好模型。** 录音不用跟上播放速度，可以用大一些、有感情的模型慢慢录。Mac 一晚上能录完一整本，手机充电的时候也能录。
2. **录好就是一本真正的有声书。** 之后在哪台设备上听都一样：旧手机也能听，不费电，不用联网，进度、划线照常同步。
3. **一次做好，处处能用。** 剧本和录音按书存、能同步。Mac 上做好的，手机直接听；手机上录了几章，Mac 上接着录。

## 三、① 写剧本：谁在说话、怎么说

### 3.1 人物小传：先把人吃透
像演员接戏前做的功课，每个主要人物一份，从原文里整理（只用读到的部分）：
- **他是谁**：多大、出身、哪里人、身份、此时的处境（黛玉：十二三岁，苏州来的，父母双亡寄居外祖母家）。
- **性格和心事**：几个关键词，加上为什么（敏感，因为寄人篱下；嘴上不饶人，因为心里不安）。
- **说话的样子**：快慢、轻重、用词、习惯，比如爱说反话、爱笑着说狠话、一急就结巴、口头禅。
- **对不同的人**：同一个人对不同的人说话完全不一样。黛玉对宝玉是赌气撒娇，对宝钗是客气里暗暗较劲，对长辈是乖巧，对丫头是体贴又有分寸。
- **声音**：一段给配音用的描述（年龄感、音色、音高、语速、口音），不写情绪。整本书这个人都用这一段。
- 人物会变：读到后面，小传跟着更新（宝玉长大了、黛玉病重了），声音描述也可以跟着微调。

### 3.2 剧本里有什么
- **演员表**：每个人物的名字、所有别名（"宝玉""宝二爷""二爷"是一个人），和他的小传。
- **每一句台词**：谁说的、**对谁说的**、**心里真正想的**（"早知他来，我就不来了"：表面开玩笑，底下是吃醋），再由这些推出这一句的**语气**，用大白话写怎么说，比如"冷笑，压低声音，话里带刺""哭腔，说到一半哽住"。
- **旁白**：也带提示，跟着情节走，比如"紧张，放慢""轻松，像在讲笑话"。
- 一句里对白和旁白混着的（"'走吧，'他说，'天要黑了。'"），拆开来各演各的。

> 为什么用导演提示，不用"高兴、生气、悲伤"这种标签：标签只有几种，人说话的样子多得多。"冷笑着反讽"和"真生气"都算生气，听起来完全不一样。有感情的语音模型直接认大白话，提示写得越像导演说戏，演得越像。

### 3.2.1 导演本：补上行内的功夫（2026-10-19 加）
只有"谁说、对谁、心里、语气"还差感觉，缺的是做广播剧、有声书的三块专业知识：

1. **表演：演"目的"和"动作"，不直接演情绪。** 每场戏先写**规定情境**（时间、地点、天气、各人身体状态、刚发生了什么）、每个人在这场戏里**想要什么**、**转折点**和**情绪线**（起、升、转、落，每拍快慢）。每句台词写**目的**（想让对方怎么样）、**动作**（一个动词：刺、试探、装傻、打圆场、耍赖……）、**内在语**（没说出口的那句话）；情绪是这些的结果。
2. **播音四个基本功：停连、重音、语气、节奏。** 每句写重音落在哪个词、在哪里停一下；整场的快慢跟着情绪线走。
3. **广播剧制作：真人说话不只是字。**
   - **接话的时机**：抢话、紧接、停一拍、停两拍，按剧本留间隔，而不是每句之间都一样长。
   - **小动静**：轻笑、吸气、叹气，只在真需要的地方，一场戏三四处以内。
   - **远近和房间**：屋里的人在同一个房间里，有一点回声；隔着门帘的远一点、闷一点；旁白不在戏里，永远贴着耳朵。远近和房间感由 App 自己处理声音，不靠语音模型。

这些写成一份**导演手册**，模型写导演本时照着它来（像 book-to-skill 那样，把专业知识整理成一份模型随时照着用的资料）。手册以后可以从播音、配音、表演的专业教材里继续补充。

### 3.3 怎么写：大部分靠规则，模型只做"选择题"
整本书都交给模型读，又慢又贵，手机也读不动。这里拆成三层，越往下越少用到模型：

1. **规则定下来的**：引号里是台词；紧挨着的"XX 道""XX 笑着说"直接认出是谁。不花算力，一大半台词这一步就定了。
2. **对话规律定下来的**：两个人你一句我一句、中间没写是谁的，按轮流说话的规律往下排，前后都有锚点时基本不会错。
3. **剩下的交给模型做选择题**：不是问它"这句是谁说的"，而是给它这一段、加上**此刻在场的几个人**，让它从里面挑一个，顺便写导演提示。题目短、答案只能从名单里选，小模型也答得准、答得快。

演员表也是一章一章长出来的：每章先找出新出场的名字，章末让模型把别名合并一次。

### 3.4 模型从哪来：App 自己带，不靠系统
- 第一版的问题是：没有 Apple 智能、没有 Key 的设备就没模型。这一版**语阅自己提供一个可下载的开源模型**（中文好、许可宽松、能商用，比如千问系列的小模型），开这个功能时下载一次，一两个 GB。
- 有了 3.3 的拆法，这个小模型只需要做选择题，现在 8 GB 内存的手机（iPhone 15 Pro 及以后、大部分新安卓）和所有 Apple 芯片的 Mac 都跑得动。
- 有 Apple 智能或自带 Key 的，可以改用它们，更快；但**不用它们也能完整做出来**。
- **还跑不动的旧设备**：用同一账户下其他设备做好的剧本（Mac 或新手机），自动同步过来。这是唯一要借别的设备的情况，第五节有分工表。

### 3.5 不剧透
- 剧本可以在后台往后写，但**人物表只给你看你读过的部分里出现过的信息**：后面才登场的人、后面才揭晓的身份都不显示。
- 录音同理：后面章节已经录好了，界面也不会提前露出人物名字。

### 3.6 认错了能改
- 气泡上点人物名字，改成别人或改成旁白；改了问一句"这一章同样的也一起改？"。
- 改过的地方只重录那几句，不动别的。以后重新分析也不会覆盖你改的。

## 四、② 选演员：每个人物造一个专属声音

- 不是从固定的几个声音里挑。现在的开源语音模型能**照着一段文字描述造出一个声音**，比如"十六岁少女，声音清亮，说话带点娇气"。
- **试音**：App 按演员表里的描述，给每个主要人物造三个候选声音，用他在书里的一句原话试读，你挑一个。不满意可以用大白话再调："再低沉一点""老一点""更冷淡"。
- **定下来就锁住**：挑中后，这个人的声音描述和"种子"（让每次造出来的声音都一样的一个数）一起存下来，以后每句都照"声音描述 + 这一句的语气"直接录（实测的做法 A，你听过选了它），从第一章到最后一章是同一个人，换设备也一样。
- **配角**：只说几句的路人不单独试音，从几个路人声音里自动分配，按性别、年龄配。
- **旁白**：一个固定的讲述者声音，你可以从几个里挑，也可以描述一个。

## 五、③ 录音：带着感情一段一段录

### 5.1 一整段一起演，再切回句子
- 一句一句单独录，每句都像重新开口，前后语气接不上。所以**一整段对话、一整段旁白一起录**，语气才连贯。
- 录完再用我们自己的"听读对齐"（FEATURES 3.4 的招牌功能，同一个引擎）找出每一句在音频里的起止时间。这样逐句高亮、点句子跳转、气泡亮起都和现在一样准。

### 5.2 谁来录：设备分工

| 设备 | 写剧本 | 录音 | 说明 |
|---|---|---|---|
| Mac（Apple 芯片） | 能，很快 | 能，比播放快，一晚录完一本 | 推荐的"录音棚" |
| 新 iPhone、iPad、新安卓（8 GB 内存及以上） | 能 | 能，比 Mac 慢；默认只在充电时整本录，平时只往前多录一两章 | 只有手机也能完整用 |
| 旧手机 | 用别的设备写好的 | 用别的设备录好的 | 打开就能听 |
| 填了 Key 的（任何设备） | 可选，最快 | 可选，云端录（豆包、ElevenLabs 等） | 收费，不是必须 |

- 不管哪台设备录的，录好的音频都同步到其他设备。
- **还没录到的地方**：刚导入的书，先录你正在读的这一章，录好几句就开始播，后面边播边录。如果实在跟不上（比如旧手机、又没别的设备），这一段先用普通朗读顶上，录好后自动换成有感情的版本，界面上标出来。

### 5.3 占多少地方
- 一本 50 万字的小说大约能听 35 小时，按听书常用的压缩，大约 400～500 MB。
- 默认只留"读到的地方往后几章"的录音，听过的可以自动清掉（剧本留着，想重听再录或从别的设备同步）。存储页里能看到每本书占了多少。

## 六、④ 播放和气泡模式

### 6.1 播放
- 和现在完全一样：倍速不变调、睡眠定时、单句循环、锁屏控制、读听同一进度。录好的音频就是一本"已经对齐好的有声书"。

### 6.2 气泡模式
- **旁白**：普通段落。
- **台词**：聊天那样的气泡，旁边圆形小头像（人物名字的第一个字），上面写名字，每个人一种淡淡的底色。
- **左右**：你决定。默认都靠左（像群聊），可以在人物页里把任意一个人设成靠右。
- **正在读的那句**：气泡亮起来，页面跟着走。自己滑开后出现"回到朗读处"和"从这里读"。
- 点气泡从这句读；长按和普通书页一样，能划线、写想法、问书伴。
- 在阅读页的 Aa 里切换：**原文排版 / 气泡**。剧本写好的章节才能切；对白太少的书不显示这个选项。
- 不听、只看也能用。墨水屏：气泡只用细线框，不带阴影和底色。

### 6.3 人物页
- 书的信息里新增"人物"：每人一张卡，写着名字、别名、性格、声音；"试音"可以重新选声音；"靠右"开关；只显示读过的部分里的信息。

## 七、还不确定、要先实测的

这几件事决定了方案细节，写代码前在你的 Mac 上实际跑一遍，用真书测：

1. **小模型认说话人准不准**：拿两三本对话多的中文小说（比如《红楼梦》一回、一本现代网文一章），人工标一份答案，对比规则 + 小模型的结果。目标：九成五以上说对。
2. **有感情的录音有多快、好不好听**：在 M2 上录同一段，测"录 1 分钟要多久"；听导演提示有没有真的演出来；同一个人物前后声音是不是一个人。

4. **整段录再切句子**：用对齐引擎切，句子边界准不准。

## 七点五、实测结果（2026-10-19，M2 MacBook Air 16 GB，外置盘 T2214/yuyue-lab）

| 测了什么 | 结果 |
|---|---|
| 带感情录音的速度（Qwen3-TTS 1.7B） | 录 1 秒音频约 0.8 秒，比播放快 |
| 三种录法 | 你听了选**做法 A**：每句直接用"声音描述 + 这一句的语气"录，每人固定种子 |
| 拆句、认说话人 | 交给模型（4B）会拆错、把"宝玉""贾宝玉"当两个人；改用**规则**后，第八回这场 11 句台词认对 10 句，剩下一句原文只写"外面人说" |
| 读懂人物（4B，手机能跑的大小） | 小传有事实错误（宝钗写成庶出），潜台词大多没读懂，**不够用** |
| 读懂人物（9B，Mac 能跑的大小） | 小传基本准确；11 句台词里约 8 句的"心里"读对了（吃醋、故作不解、被说中心事），宝玉要斗篷那句还是没读出"他要走"；有几句语气演过了头（通报一句"林姑娘来了"写成惊慌失措） |
| 写剧本的速度（9B，M2） | 一个人物的小传约 100 秒；这场 24 段的剧本约 170 秒。照这个速度，一整部《红楼梦》在 M2 上写剧本要好几个晚上 |

| 照导演手册写导演本（9B） | 一大段古文里，9B 会把谁说了哪句搞混：已经告诉它说话人，还把黛玉的话当成宝钗说的，把黛玉的褂子安到宝玉身上。**读不准《红楼梦》这种书** |
| 强模型写的导演本 + 本地录音 | 做了前后对比页（out/对比.html），等你听 |
| 本地 9B **一句一句**写导演本（说话人写死在问题里，前文用"宝钗：……"的剧本格式） | 12 句台词约 9 句读对，和参考导演本很接近（"你们俩倒是热闹，我来做什么"几乎一字不差）；宝玉要斗篷那句仍没读出"他要走"，过场话偶尔加戏。速度：前文读一遍 27 秒，之后台词每句约 10 秒、旁白约 3 秒 |


**由此定下的**：
- 拆句、认人用规则，模型只做选择题和"读懂人物"。
- "读懂人物"至少要 Mac 上的 9B 这一级，或者云端模型；手机自己写剧本效果不够，手机上默认用 Mac 写好同步过来的剧本，或者填 Key 交给云端写。
- 旁白的语气要少写：只写节奏和情绪，不写"突出某某的从容"这类导演心里话。
- **本地写导演本可行**：照"一句一句问 + 说话人写死 + 剧本格式前文"，Mac 上的 9B 就能写到接近强模型的水平。速度上，M2 一晚上（8 小时）大约能写 2500～3000 句台词，相当于《红楼梦》十几回；所以默认只往前做"读到的地方往后几回"，新一些的 Mac 会快很多，填了 Key 可以交给云端整本做。
- 写导演本要一句一句地问（说话人由规则定好、写死在问题里），不要让模型一次写一整场；整场分析也只写原文里明确写到的事。
- 还要做：试云端模型（豆包、DeepSeek、Claude 等）写导演本的准度和费用；试一句一句问的本地 9B。给模型更多前文（一整回而不是 2500 字）、让它先说"这一回发生了什么"再写语气、试新一些的 Mac 和云端模型的速度和准度。

## 九、已经定下的（2026-10-19）

1. "先录制、再播放"：可以接受。
2. 跑不动模型、没有别的设备、也没填 Key 的旧设备：**不显示**这个功能（有的人本来就不需要）。
3. 气泡下面的"语气"（这句话该怎么说，比如"笑着说，话里带一点酸"）：只在正在读的气泡下面显示，排版里能关。等你看过原型再定默认开不开。
4. **本地和云端都要支持**：本地在 Mac 和新手机上录，免费；填了 Key 可以用云端录，更快。两种能混着用（比如剧本本地写、录音交给云端）。
5. 实测放在外置硬盘 T2214 的 `yuyue-lab` 文件夹里。
