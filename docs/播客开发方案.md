## 一、做成什么样

参考 hacker-podcast（miantiao-me/hacker-podcast）：它每天抓 Hacker News 热门文章和评论，用大模型逐篇摘要，再写成两位主播的对谈稿，合成语音，发布成公开播客。

语阅学它的做法，有三处反着来：

| | hacker-podcast | 语阅 |
|---|---|---|
| 信息从哪来 | 固定 Hacker News | **用户自己加**：任何 RSS、网页、Hacker News，以及语阅里自己的书、划线、生词 |
| 在哪生成 | 作者的 Cloudflare 服务器 | **用户自己的设备**，用用户在书伴里配好的模型 |
| 给谁听 | 发布出去给所有人 | **只给自己听**，不发布 |

一句话：**每个人有一档自己的电台，内容是自己关心的，主持人和声音是自己挑的。**

它和普通播客最不一样的地方，是语阅本来就擅长的：
- **稿子就是文字**，所以每一集天然能听着读：逐句高亮、点一句从这句听、划线进笔记、点词查义。
- **每段都带出处**，点一下打开原文。
- **听到一半能追问**：问书伴"这条展开讲讲"，它就接着聊（第三期）。

> 许可证：hacker-podcast 是 AGPL-3.0，和 Animeko 一样**只借思路，不拷代码**，提示词也自己写。

## 二、现在有什么能用（2026-10-31 查的代码）

| 要用的 | 现在 | 怎么用 |
|---|---|---|
| 大模型 | 书伴的"添加服务商"三端都有了，`Companion.answer(system:prompt:)` | 写稿直接用用户选的服务商和模型，不另配 |
| 朗读 | 三端都有：一句一句向"声音"要音频再播，系统声音、云端声音都接好了，云端整章缓存 | **稿子本身就是一句一句的**，直接进现有的播放器，不用先合成整段 MP3 |
| 锁屏、耳机、倍速、睡眠定时 | 都在 Player 里 | 原样用 |
| 分角色朗读 | 没做（听书开发方案里排在 1.0 之后） | 播客的对谈稿每句已经写明是谁说的，只要做"按说话人换声音"这一小块，不用猜谁在说话 |
| 书页 | 三端都有 | 稿子在书页里打开，和读书一样 |
| 同步日志 | 有 | 记节目设置、每集听到哪 |
| XML / HTML 解析 | 核心里有 roxmltree、html5ever | 解析 RSS、抽网页正文 |
| 联网 | 都在原生（URLSession / OkHttp），核心不联网 | 照旧：原生下载，交给核心解析 |

**这一版比订阅传统播客还省事**：不用新写一种播放器，不用下载大音频文件，也不用转写。

## 三、功能清单

### 3.1 节目：用户自己建
一个用户可以有几档节目，比如"每天早上的科技新闻""周末的读书回顾""英语生词对话"。每档节目设：

- **名字、封面**：封面自动按名字配色生成，也能换。
- **信息源**：见 3.2。
- **什么时候出新一集**：每天几点，或每周几，或只在手动点"生成一集"的时候。
- **多长**：约 5 / 10 / 20 分钟（换算成字数，告诉模型）。
- **形式**：单人播报，或两人对谈。
- **主持人**：每人一个名字、一句"他是什么样的人"（比如"产品经理，爱打比方""工程师，讲原理"），以及用什么声音、快慢高低。默认照原文平实地念，不加语气（和听书的原则一样，用户定）。
- **语言**：中文、英文……可以和信息源的语言不一样。比如英文新闻做成中文节目，或者中文内容做成英文节目练听力。
- **想多听什么、少听什么**：一句话写给编辑，比如"多讲开源工具，少讲融资"；另外可以列几个不要的词。

### 3.2 信息源：用户自己加
| 种类 | 例子 | 怎么取 |
|---|---|---|
| **RSS / Atom** | 博客、新闻站、少数派、V2EX、arXiv 分类、GitHub 项目的发布更新、Reddit 板块、YouTube 频道（只取标题和简介） | 原生下载，核心解析；有正文就用正文，只有摘要的就去取原文 |
| **Hacker News** | 首页热门、Show HN、Ask HN | 用它公开的接口，**连评论一起取**，稿子里能讲"社区怎么看" |
| **网页** | 某个页面，比如公告页、更新日志 | 定时去看，有变化才算新内容 |
| **稍后听** | 在浏览器或别的 App 里"分享到语阅"的一篇文章、一个 PDF | 进下一集，或者单独生成一集 |
| **语阅里自己的东西** | 这周的划线和想法；在读的书读过的部分；生词本 | 不联网。比如"把这周的划线串起来聊聊"；"用我的生词编一段英文对话" |

- 加信息源时可以粘贴网址，App 自己找出它的 RSS（网页里一般写着 RSS 在哪）。
- 内置几个**一点就加的模板**（见第六节第 4 条），新用户不用知道什么是 RSS。
- 每个信息源能单独设每次最多取几条，也能暂停。
- **只用新内容**：用过的文章记下来（按网址），下一集不再重复讲。

### 3.3 一集是怎么做出来的（在用户自己的设备上）
```
1 取新内容 ──► 2 取正文 ──► 3 挑选 ──► 4 逐篇摘要 ──► 5 写稿 ──► 6 标题和简介
  （原生联网）   （核心抽正文）  （大模型，只看标题）  （大模型，每篇一次）  （大模型，一次）  （大模型）
                                                                           │
                                               稿子：一段一段，每句写明谁说、出处是哪篇 ◄─┘
                                                                           │
                                               7 听：现有播放器一句一句念，每个主持人用自己的声音
```

- **第 3 步挑选**：新内容太多时，只把标题和来源交给模型，按"想多听什么"挑出 N 篇，省钱也省时间。
- **第 4 步摘要**：每篇单独一次，做完一篇存一篇。中途断网、关掉 App，下次从断的地方接着做，不重来。
- **第 5 步写稿**：要求模型按固定格式交回（每段：话题、几句台词；每句：谁说、说什么、出自哪几篇）。核心检查格式，不合格就重试一次，还不行就告诉用户哪里出错了。
- **第 7 步不用先合成**：稿子直接交给播放器，和朗读一本书一样。用云端声音时，提前把整集合成好缓存起来，通勤路上没网也能听。

### 3.4 什么时候生成、在哪台设备生成
- 没有服务器，就只能靠用户的设备。所以每档节目选一台**负责生成的设备**，默认：有 Mac 就是 Mac，没有就是手机。只有这一台会生成，避免两台设备各生成一份。
- **Mac**：到点就生成（开着语阅，或设了开机启动在菜单栏后台）。
- **iPhone / iPad**：系统允许的时候在后台做（一般是夜里充电、连着 Wi-Fi），系统不一定给时间；所以打开 App 时，如果该出的一集还没出，就当场生成，显示"正在写第 3 篇，约 1 分钟"。
- **Android**：用系统的定时任务（WorkManager），比 iPhone 准时。
- 生成好的稿子是文字，体积很小，走"书文件"那条路同步到其他设备；**每台设备自己用自己的声音念**，不同步音频。

### 3.5 听
- 播放器、锁屏、耳机、倍速、睡眠定时（"本集结束""本段结束"）都和听书一样。
- 稿子在书页里，正在念的那句亮起，页面跟着走；点一句从这句听。
- 每段开头有一行**出处**（网站名 · 原文标题），点开看原文。
- 划线、想法进"笔记"，出处写节目名、哪一集、原文链接。
- 外文节目能点词、生词标出来，和外文书一样。
- 每集记住听到哪，跨设备同步；听完自动标为已听。在听的一集和在读的书放在一起（"接着听"）。
- 统计：收听时长包含播客，"我的"里单独一行。

### 3.6 越听越合口味（第三期）
- **接着聊这条**：听到某段时按一下，书伴根据这篇原文再写一两分钟，接在这段后面念。
- **少讲这个**：某段上点"少讲这种"，自动加进这档节目的"少听什么"。
- **问书伴**：在稿子上选中一句问，回答带原文出处，和问书一样。

### 3.7 不做
- 发布成公开播客、导出音频分享给别人：要服务器，而且拿别人的文章做成音频发出去有版权问题。分享只分享文字（一句话 + 原文链接）。
- 订阅别人的传统 RSS 播客：见第六节第 1 条。
- 账号、榜单、推荐、托管的大模型。
- 自动配背景音乐、音效：和听书的原则一样，先做平实的；以后真有人要，再做成开关。

## 四、技术做法

### 4.1 核心（Rust，三端共用）
- **信息源**：解析 RSS 2.0 / Atom；Hacker News 接口的返回；从网页里找 RSS 地址；**抽网页正文**（去掉导航、广告、评论框，照 Readability 的思路用已有的 html5ever 写，不加依赖）。
- **去重**：每篇按规范化后的网址算编号（blake3），记下"哪档节目用过"。
- **给模型的材料**：每篇截到一定长度；按节目设置拼出每一步的提示词。**提示词放在核心里**，三端一模一样。
- **稿子**：检查模型交回的格式，切句子（用已有的断句），存成和书一样的"章节 → 句子"，再加上每句是谁说的、出处是哪篇。这样书页、播放器、笔记都不用为播客改。
- **同步日志里记**：
  - `show/<id>`：节目设置（名字、信息源、时间、长度、形式、主持人、语言、多听少听、负责生成的设备）
  - `episode/<id>`：哪档节目、哪天、稿子文件、听完没有
  - `progress/<集>/<设备>`：听到哪一句（和书的进度一样）
  - "用过的文章"只在负责生成的那台设备上记，不进日志
- **主持人的声音**存在各设备本机（和"每种语言用哪个声音"一样），因为每台设备能用的声音不同。

### 4.2 原生（各平台各写一份，越薄越好）
- 联网下载信息源、调用大模型（书伴现成的）、后台任务。
- 播放器加一件事：**每句按说话人选声音**。这是分角色朗读里最简单的一块（谁说的已经知道了），做完分角色朗读以后也直接用。

### 4.3 界面（照"先画原型、你确认、再写代码"）
- **Mac**：侧栏"播客"去掉"即将推出"。点进去：上面是几档节目的封面，下面是最新几集；右上"新建节目"。
- **iPhone / iPad、Android**：入口见第六节第 5 条。
- 原型放 `docs/design/播客.html`，要画：
  1. 播客首页（有节目、一档都没有两种）
  2. 新建节目：选模板或从空白开始 → 加信息源 → 主持人和声音 → 时间和长度
  3. 加信息源（粘贴网址、模板、语阅里的东西）
  4. 一集正在生成（第几步、写到第几篇）、生成失败（哪步、为什么、重试）
  5. 听一集：稿子在书页里，每段的出处行，两位主持人怎么区分

## 六、需要你确认的

1. **传统播客（订阅别人的 RSS 播客）还做不做？** 建议**这次不做**，先把 AI 电台做好。以后要做，播放器得另加一种整段放的方式（见作废的第一版），工作量不小。
2. **默认形式**：
   - A. 两人对谈（hacker-podcast 的做法，最像播客）。系统声音念对谈会比较呆，建议配云端声音。
   - B. 单人播报（最省钱，系统声音也能听）。
   - 建议：新建节目时两种都摆出来让用户选，**模板默认两人对谈**。
3. **苹果设备上的本机模型**（Foundation Models，免费、不联网）能一次读的字很少，只够做"三五条、单人、五分钟"的短播报。要不要允许用它？建议允许，但只开放这种短的，长的要用户配服务商。
4. **内置模板**，我建议这几个，你增删：
   - 科技：Hacker News 热门（带评论）、少数派、36 氪
   - 开源：GitHub 上我关注的几个项目的发布更新（填项目名）
   - 学术：arXiv 某个分类（选分类）
   - 读书：这周的划线和想法
   - 外语：用我的生词编一段对话
5. **手机上的入口**：书架筛选里加一项"播客"（全部 / 书 / 有声 / 播客），在听的一集和在读的书放在一起。建议这个，不在底栏加图标。
6. **国区**：TECH 第十一节说国区对生成式 AI 要额外审核；AI 生成的新闻类音频还涉及"深度合成"的规定。国区版大概要先关掉这个功能，和"自带 Key 接 AI"按地区开关一起处理。
